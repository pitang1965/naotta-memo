# 0006. 強さの判断を伴わない中立の「メモ」状態を持つ

- ステータス: 承認
- 日付: 2026-08-19

## 背景

グリルの段階で、状態は6値(`worse`/`same`/`better` ＋ `start`/`resolved`/`relapse`)に整理し、
曖昧な `other`(その他)を**廃止**した。理由は「メモをどの状態にも添えられるようにしたので、
『病院に行った』のような出来事は `same`(変わらず)＋メモで書ける」というものだった。

しかし実装して実際に使うと、記録カードで**メモを入力しても、`worse`/`same`/`better` の
いずれかを押すまで保存できない**。「強さの判断はしたくないが、メモ(出来事)は残したい」場面で、
確定する導線が無く不便だった。`same` に押し込めるのは「変化なし」という判断を暗に含み、正確でない。

(登録フォームには明示の「保存」を付けたのに、日々の記録側にはメモ単独の保存が無い、という
非対称も混乱を生んでいた。)

## 決定

**強さの判断を伴わない中立の状態 `memo`(メモ)を追加する。**

- 記録カードに「**メモだけ記録**」を置き、状態を選ばずメモだけを1エントリとして保存できる。
- `memo` エントリは active/resolved を変えず、現在のエピソードに属する(導出は `worse`/`same`/`better`
  と同じ扱い)。履歴・通院要約では「メモ・◯◯」と表示する。
- これは廃止した `other` の**復活**にあたるが、「その他」という曖昧な受け皿ではなく、
  「状態ではないメモ/出来事」という用途を明確にした名前 `memo` とする。

## 結果

**良い方向:**
- 「病院に行った」等の出来事を、強さを偽らずに残せる。
- 登録・記録・編集すべてが「明示的に保存」で一貫する(メモ単独の確定導線ができた)。

**代償・要フォロー:**
- 状態値が1つ増える(7値)。表示・エクスポート・編集UIで `memo` を扱う必要がある。
- 過去に「`other` 廃止」と決めた経緯と矛盾するため、本 ADR と CONTEXT で理由を明記して打ち消す。

採用しなかった案:

- **`same`(変わらず)として保存**: モデルを増やさないが、「変化なし」という判断を偽って含めてしまう。
- **追加しない(状態と一緒にのみ確定)**: 出来事メモのために毎回 強さを選ばせるのは不自然で、
  実利用の不便が解消しない。
