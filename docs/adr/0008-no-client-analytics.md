# 0008. 利用状況の計測はクライアントに入れず、配信基盤の集計だけを見る

- ステータス: 承認
- 日付: 2026-09-10

## 背景

紹介ページと共有導線を作った(ADR 0007)ものの、**誰がどう使っているのかまるで分からない**。
作者として当然の欲求として、PostHog のようなプロダクト分析ツールの導入を検討した。

しかし、このアプリは既に**無条件の約束**を公開している。プライバシーポリシー第3節:

> 運営者は、あなたの健康データや氏名・メールアドレス等の個人情報を**収集しません**。
> **アクセス解析ツールや広告も使用していません。**

同じ趣旨が利用規約、紹介ページの「考え方」、紹介ページのフッターにもある。
さらに ADR 0004 は、AI 取り込みという機能そのものを捨ててまで
「サーバーなし・キーなし・端末内完結」を守った記録であり、ADR 0005 は
「クライアント専用、サーバー/DB/認証は持たない」を決定として残している。
端末内完結は思いつきの制約ではなく、対価を払って選んだ設計思想である。

## 決定

**クライアント側の利用状況計測ツール(PostHog、Google Analytics、Cloudflare Web Analytics 等、
ビーコンやスクリプトを注入する方式のすべて)を導入しない。**
利用状況は、配信基盤である Cloudflare Pages が配信に伴って既に保持している
リクエストの集計だけを見る。これはクライアントに 1 バイトも足さず、
プライバシーポリシー第3節の後半で**すでに開示済み**の範囲に収まる。

「どの機能が使われているか」を知りたくなったときは、統計ではなく
**利用者に直接聞く**。連絡先は紹介ページのフッターと設定タブにある。

Cloudflare の *Web* Analytics はビーコンを注入する方式なので、
名前が紛らわしいが本 ADR が禁じる側に入る。配信基盤が自動的に持つ集計とは別物。

## 結果

**良い方向:**

- 公開済みの約束を一文も書き換えずに済む。**約束は機能と違って、足したり引いたりできない。**
  「解析していません」と言って信用してもらった後で撤回するのは、一度しか使えないカードを切ること。
- 口コミの導線を作った直後という時期に、紹介ページで最も強い売り文句
  (「記録は、端末の中だけ」)の根拠を自分で弱めずに済む。
  友人に薦められた人がその一文を読んで健康情報を入れる、という鎖を壊さない。
- 健康アプリ固有の問題を回避できる。記録の中身を一切送らなくても、
  **操作イベントそのものが健康の情報に近い**。「毎日『悪化』を押している」
  「3 週間ぶりに開いて『治った』を押した」から体調の波はかなり読める。
  一般的な SaaS では無害な既定値(autocapture、distinct_id の永続化)が、ここでは意味が変わる。
- サードパーティのスクリプトが増えないので、初回描画も Service Worker のキャッシュ設計も
  そのまま保てる。

**代償・要フォロー:**

- **どの機能が使われていないかが分からない。** 削る判断・直す判断を、
  データではなく推測と直接の声で行うことになる。
- 定着率・離脱箇所・エラー発生率が見えない。不具合は利用者が報告してくれない限り気づけない。
- Cloudflare 側の集計で実際に何がどこまで見えるかは、Direct Upload プロジェクトの
  ダッシュボードで確認が必要(本 ADR の時点で未確認)。期待したほど見えない可能性がある。

採用しなかった案:

- **PostHog を入れ、プライバシーポリシーを書き換える**: 欲しい情報は最も正確に得られる。
  だが公開済みの無条件の約束を撤回することになり、しかも人に薦めてもらう仕組みを
  作った直後というタイミングが最も悪い。**計測できない痛みより、信用を失う痛みのほうが
  取り返しがつかない**と判断した。
- **Cloudflare Web Analytics を使う**: Cookie を使わず軽いが、ビーコンを注入する以上
  「アクセス解析ツールは使用していません」は同じく嘘になる。約束の観点では PostHog と同類。
- **将来に備えて今から計測基盤だけ持っておく**: 利用者が数人〜数十人の段階では、
  統計より 1 人に直接聞くほうが桁違いに情報量が多い。基盤を先に持つ理由が弱い。

## 将来これを覆すとき

覆すこと自体は禁じない。ただし**最低限これをやる**こと:

1. プライバシーポリシー第3節の書き換えと、最終更新日の更新
2. 紹介ページにも明記する(隠して入れない)
3. autocapture は無効にし、送るイベントを手で選ぶ
4. セッションリプレイは入れない
5. 症状名・メモ・生年月日がイベントのプロパティに乗らないことを、実際に通信を見て確認する
