# 0001. 症状は再発しうる「継続スレッド」として持ち、エピソードは導出する

- ステータス: 承認
- 日付: 2026-08-17

## 背景

「なおったメモ」は症状を「発症 → 経過 → 治癒」で追う。しかし多くの症状(例: 片頭痛)は
**再発する**。同じ人が月に1〜2回、同じ頭痛を繰り返すのは普通のことだ。

プロトタイプのデータモデルでは `Issue` が単一の `startDate` と単一の `resolvedDate` を持ち、
1つの `Issue` = 1回の発症〜治癒の山、を暗黙に前提していた。この前提のままだと、
「再発」を表現する手段が「resolved → active に戻す undo」しか無く、繰り返す症状は
別々の `Issue` として登録するしかない。

このアプリの差別化(悪化→治癒の期間と気圧変動を突き合わせる, §6.4)と通院用途
(「この頭痛は今月3回、毎回2〜3日」)は、いずれも**1回の発症〜治癒の山=エピソード単位**の
分析を必要とする。再発が別 `Issue` に散ると、これらが束ねられない。

## 決定

**症状(Issue)を、再発しうる継続的なスレッドとしてモデル化する。** 具体的には:

1. 1つの `Issue` は `active` と `resolved` の間を**何度でも遷移**できる。
2. ライフサイクルの節目(`start` / `resolved` / `relapse`)を、経過の記録(`worse` /
   `same` / `better`)と同じ**チェックインのタイムライン上のイベント**として記録する。
3. `Issue` の現在状態(active/resolved)は、**最新の節目イベントから導出**する。
   単一フィールドの `resolvedDate` は廃止し、治癒日はイベント列から求める。
4. **エピソード(1回の発症〜治癒の山)は独立実体として保存しない。**
   `start`/`relapse` で始まり `resolved` で終わる区間として、イベント列から導出するビューとする。

採用しなかった案:

- **モデルB: 発生ごとに新しい `Issue`**。データ構造は単純(プロトタイプのまま)だが、
  「同じ症状の再発」という関係が失われ、エピソード横断の気圧分析ができず、
  症状名の表記ゆれ問題(§7)が悪化する。

## 結果

**良い方向:**
- 「今月◯回」「毎回何日で治る」などの再発パターンを、1つの症状の中で表現・分析できる。
- 気圧×エピソードの突き合わせが、症状スレッド内で一貫して行える。
- 履歴に同名の症状が乱立しない。名寄せ問題が起きにくい。

**代償・要フォロー:**
- プロトタイプの `Issue.resolvedDate`(単一)を廃止し、節目イベント列から導出する構造へ
  作り替える必要がある。プロトタイプからの移行は単純な流用では済まない。
- 「経過日数」の定義を決める必要がある(最初の発症からの通算 / 現在のエピソードの開始から)。
  → 別途決定。
- 「本物の再発(relapse)」と「治癒の誤操作を取り消す undo」を、データ上どう区別するかを
  決める必要がある。→ 別途決定。
