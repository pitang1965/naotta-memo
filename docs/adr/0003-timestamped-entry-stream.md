# 0003. 記録は「時刻つきエントリの流れ」に統一する(1日1件制約の撤廃)

- ステータス: 承認
- 日付: 2026-08-18

## 背景

プロトタイプ(素案§7)は「同じ症状は1日1件・複数回の記録は上書き」を**既知の制約**として
明記していた。日単位の質的記録(`worse` / `same` / `better`)を前提とした素直な設計だった。

しかしこの前提は、2つの現実的な反例に耐えられなかった:

1. **発熱の体温**: 1日に何度も測る数値(朝37.2 → 昼38.5 → 夜39.1)。「昨日より worse」ではなく
   数値そのものの日内推移が要る。しかも観察は数値に限らない(尿の色、発疹の広がり等、
   定性的な日内変化もある)。
2. **日内の状態変化**: `worse/same/better` は「その日の総合判断」ではなく「**記録した瞬間の
   判断**」。午後に熱が下がって楽になれば、午後の時点で `better` を記録したい。1日1件だと
   朝の `worse` が失われる(上書き)、あるいはメモにしか残らない。

この2つは同じ形をしている——どちらも「**時刻つきの1エントリ**」。「1日1件のチェックイン」と
「メモへの追記ログ」という2つの別々の仕組みは、本来1つの概念だった。

## 決定

**症状の記録を「時刻つきエントリの流れ」に統一する。**

1. 症状のタイムラインは、**時刻つきエントリの列**。
2. 各エントリは「状態(`worse`/`same`/`better`/`start`/`resolved`/`relapse` のいずれか)」と
   「メモ」を任意で持つ(Phase 2 で数値も)。
3. **1日に何件でも**置ける。1日1件の制約は撤廃する。
4. タップするたびに新しいエントリが**足される**。上書きしない(朝の記録が夜の記録で消えない)。
5. 「今日の状態」は、その日の**最新の状態エントリ**で表す。
6. start/resolved/relapse も worse/same/better も、すべて同じ流れの中のイベント。
   [エピソード](ADR 0001)はこの流れから導出する。

採用しなかった案:

- **② 1日1件を維持し「最後の判断が勝つ」**: モデル変更は最小だが、朝の `worse` が状態としては
  消えてメモにしか残らず、発熱の複数回計測も構造的に扱えない。日内変化を素直に表現できない。

## 結果

**良い方向:**
- 発熱の複数回計測も、午後 better の日内変化も、そのまま記録できる。
- 「1日1件＋追記ログ」の二重構造が1つに畳まれ、モデルが簡潔になる。
- ADR 0001 のエピソード導出はむしろ純化する(すべてが時刻つきイベントになる)。
- 記録は常に"足す"ので、静かなデータ消失が構造的に起きない(記録の訂正方針とも整合)。

**代償・要フォロー:**
- 「今日の状態」の表示に導出ルールが要る(= その日の最新の状態エントリ)。
- 履歴が1日複数エントリになりうるため、表示は日でグルーピングして読みやすさを保つ必要がある。
- 数値の構造化・グラフ化・自動集計(最高体温など)は本 ADR の範囲外。Phase 2 の「計測」で扱う。
