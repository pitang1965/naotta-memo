# 0004. 既存メモの取り込みは、アプリ内AIではなく外部で用意した構造化CSVで行う

- ステータス: 承認
- 日付: 2026-08-18
- 置換対象: ADR 0002(廃案)

## 背景

導入前に書き溜めた体調メモを取り込む機能(§6.5)について、ADR 0002 では
「BYOK でブラウザから Claude を直接呼び、自由文を解析する」方針を採った。これはサーバーなしで
高精度を得られる一方、弱点があった:

- 生の Anthropic API キーを localStorage に置く。
- `dangerouslyAllowBrowser` でブラウザから直接LLMを叩く構成は、一見して不穏。
- キー設定という前準備がユーザーに要る。

このアプリは個人用・非商用・端末内完結(§6)を思想の核とする。取り込みは**一度きりの移行作業**で
毎日の導線ではない。ならば「解析の知性」をアプリに内蔵する必然性は薄い。

## 決定

**取り込みは、外部で用意した構造化CSVの読み込みで行う。** アプリ内でのAI解析(ADR 0002)は廃案とする。

1. AI解析が必要なら、ユーザーが**アプリの外**(手元のAIツール等)で自由文メモを
   「症状名・日時・状態・メモ」の**CSV**に整形する。アプリはそのきれいなCSVを受けるだけ。
2. CSVは **1行 = 1つの時刻つきエントリ**(症状名・日時・状態・メモ)。
3. **同じ症状名の行は1スレッドに束ねる。エピソードの区切りは状態列の `resolved` / `relapse` 行で
   ユーザーが制御**する(CSVを用意するのは本人なので意図を状態列に込められる)。細かい分割は
   取り込み後に記録の訂正(編集/削除)で直せる。
4. 取り込みは**追加(マージ)**であって上書きではない。ADR 0003 により全記録が加算的な
   時刻つきエントリなので、マージは「(症状, 日時) のエントリを足すだけ」で済む。
5. **プレビュー必須**。行ごとに取り込む/除外/編集でき、不正な行は弾いて既存データは無傷。
6. JSONバックアップの取り込み(= 上書き復元・ADR相当の §6.1 方針)とは**別物として併存**する。
   CSV = 人が用意する過去分の移行(追加)、JSON = アプリデータの正確な復元(上書き)。

## 結果

**良い方向:**
- 生の API キーを端末に置く必要がなく、ブラウザからLLMを直接叩く不穏さも消える。
- サーバーなし・キーなし・CORS問題なしで、純粋にクライアントでCSVをパースするだけ。
- 「アプリが勝手にテキストを外へ送らない」形になり、プライバシー姿勢がより強くなる。
- AIを使いたい人はアプリの外で使える。知性は人間側＋外部ツール、アプリは構造化データを受けるだけ。
- ADR 0003 のおかげでマージが素直に成立する。

**代償・要フォロー:**
- 自由文からの構造化(CSV作成)の手間はユーザーに移る。AIツールの利用有無も本人任せ。
- CSVの実装上の注意: Excel対応で UTF-8(BOM)、メモ内のカンマはクオート、日時・状態列の形式検証。
- 画像・スクショからの取り込み(ADR 0002 が想定した将来案)は、この方針では別途検討が要る。

採用しなかった案:

- **ADR 0002(アプリ内 BYOK AI解析)**: 高精度だが、キーの端末保存とブラウザ直呼びの弱点があり、
  一度きりの移行のためにその複雑さを常設するのは割に合わない。
